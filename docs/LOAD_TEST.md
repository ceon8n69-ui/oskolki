# Нагрузочное испытание — этап 2

Запуск: `npm run load-test -- --turns 5 --units 2000` (нужна PostgreSQL в `DATABASE_URL`; данные партии остаются в БД).
Только расчёт без БД: `npm run bench -- --preset world256 --units 2000`.

Условия: карта 256×256 (65 536 клеток), 32 игрока (31 бот + 1 человек без приказов), ~2 140 отрядов, 140 нейтральных городов. Один процесс Node 22, локальная PostgreSQL 16, контейнер разработки (сопоставим с минимальным тарифом Railway).

| Показатель | Значение |
|---|---|
| Старт кампании: генерация мира в отдельном потоке + запись 256 чанков и состояния | ~5 с (сервер в это время отвечает на другие запросы) |
| Чистый расчёт хода (`resolveTurn`) | 160–220 мс |
| Полная обработка хода: ИИ 31 бота + расчёт + запись в БД, одна транзакция | 1,0–3,5 с |
| Событий за ход | 2 100–3 300 (220–530 КБ в БД) |
| Снимок хода в БД | ~52 КБ (было ~3 МБ до сжатия видимости) |
| Загрузка состояния из БД без кеша | ~16 мс |
| Ответ `/state` одному игроку | ~13 КБ |
| 16 чанков на экран (`/chunks`) | ~33 КБ |
| Память процесса | heap ~18 МБ, rss ~340 МБ |

## Повтор после этапа 3 (v0.4)

С народами, снабжением, лечением, командирами и постройками: полная обработка хода 1,0–3,1 с, событий 3 700–5 000 (520–750 КБ), снимок ~62 КБ, `/state` ~25 КБ, 16 чанков ~41 КБ (добавлен слой снабжения). Чистый расчёт правил — 260–400 мс.

## Выводы

- Целевой состав этапа 4 (32 игрока, 2 000 отрядов, ход 6 часов) укладывается с большим запасом; узкое место — ИИ ботов (до ~2 с на 31 бота), а не правила и не БД.
- Расчёт хода выполняется внутри транзакции: приём приказов этой партии ждёт её окончания (секунды), другие партии не затрагиваются.
- Видимость хранится битовыми масками и сжимается в снимках — объём на ход упал в ~60 раз.
- Состояние хода кешируется в памяти до следующего расчёта; номер хода сверяется с БД на каждом запросе, поэтому кеш безопасен при нескольких инстансах.

## Что проверить на Railway

Повторить `npm run load-test` против отдельной базы Railway (сетевые задержки до БД увеличат время записи). Лимит игроков поднимать только по результатам этой проверки.
