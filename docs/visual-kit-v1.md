# Визуальный набор Союза v1 — для интеграции с клиентом Клода

## Состав
`web/art/kingdom-art.js` — независимый ES-модуль Canvas 2.5D: изометрические клетки с боковыми гранями, вода, хвойные и лиственные деревья, горы, мост, ферма, замок, страж и лучник. Модели рисуются кодом, внешних изображений, шрифтов и зависимостей нет. `web/art/preview.html` — отдельная визуальная мастерская с переключением ожидания, движения, выстрела и строительства.

Это первый набор простых объёмных форм, а не окончательная детализация концепта. Ближняя атака поддерживается параметрами модели; переключатель «Атака» в мастерской демонстрирует лучника. В игре набор пока не подключён.

## Граница ответственности
Модуль не вызывает API, не хранит игру и не считает урон. Координаты, видимость, принадлежность, здоровье, события и их время получает от SDK. Не подменять TimelinePlayer таймерами примера и не переносить demo-цикл в игру.

## Камера
`project(x,y,z,camera)` возвращает экранные координаты основания модели. `unproject(sx,sy,camera)` — точное обратное преобразование плоскости z=0. Camera: `{x,y,size,width,height}`; size — половина ширины клетки. Логические координаты клетки обозначают её центр, края ±0.5. Для выбора клетки округлять x и y до ближайшего целого. Сначала проверить границы карты. Точка на высокой башне не является основанием соседней клетки: приоритет выбора интерактивных объектов можно реализовать через сохранённые экранные hitbox.

При переходе существующего клиента на изометрию изменить вместе: tileToScreen, screenToTile, pan, пределы видимых чанков и отрисовку подсветки/маршрутов. Видимую область определять обратной проекцией четырёх углов с запасом на высокие модели. Ось движения пальца: dxWorld=(dx/size+dy/(size*.5))/2, dyWorld=(dy/(size*.5)-dx/size)/2. Не менять сетку движка и findPath.

Сначала нарисовать поверхность, затем отсортировать здания, декорации и юнитов по x+y. Полупрозрачные устаревшие сведения рисовать с меньшей alpha. Не рисовать неизвестные клетки и скрытые цели только ради красоты. Модели нельзя получать из полного серверного мира: источником остаётся отфильтрованный StateResponse.

## Соответствие данным клиента
- `ViewUnit.type`: archer/ranger → лучник; infantry/spearman/shieldbearer → пехотная модель. Остальным классам временно оставить существующий условный знак, не выдавать одинаковую модель за завершённый класс.
- Цвет брать из `st.view.players.find(p=>p.id===u.owner)?.color`, валидировать как HEX.
- `hp`: нормализованное значение `u.hp/u.maxHp`.
- `selected`: `u.id===selected`.
- Размер модели задаётся camera.size. DPR применяется один раз через transform контекста, не к camera.size.
- В спокойном состоянии time — время кадра. Для анимации шага лучше передавать время шкалы событий с учётом скорости воспроизведения.

## Подключение TimelinePlayer
Использовать уже имеющиеся `displayUnits()` и `PlaybackStep`:
1. move: интерполированные x/y из SDK + `state:'walk'`, `progress:p`.
2. attack/counter ближнего типа: `state:'attack'`, progress=p. Не суммировать смещение dx/dy старого клиента и внутренний выпад модели: выбрать один эффект.
3. projectile: `drawProjectile(painter,event.from,event.to,p)` в отдельной стадии полёта.
4. impact: `drawImpact(...)`, изменение отображаемого HP и всплывающая цифра из подтверждённого события.
5. unit_destroyed: показать краткое `state:'defeat'`, затем скрыть по финальному состоянию.
6. building_completed/city_grew: переход между визуальными стадиями только после серверного события. `progress` у drawCastle — визуальная стадия, не фактический процент строительства.
7. capture: сменить цвет после city_captured; оспариваемый город сохранить в цвете владельца, добавить отдельный маркер.

При пропуске сразу рисовать конечный StateResponse. При reduced motion убрать подпрыгивание, колебания флага, крупные выпады; подтверждённые перемещения и значения HP остаются видны. Все значения progress зажимать в 0..1. Ни один эффект не выдаёт ресурсы и не инициирует атаку.

## Палитра и UI
Синий Союза #326cbd, зелёный #43834e, золотой акцент #efba56, тёплый камень #eddfbb, тёмно-синий интерфейс #20364e, вода #47acb6. Нужны крупные читаемые формы и спокойный фон. Свет сверху слева, правая грань темнее. Основные кнопки не меньше 44 CSS px, safe-area Telegram учитывать отдельно. Макет мастерской не заменяет производственный HUD.

## Проверки перед слиянием интеграции
Проекция/обратная проекция; корректное выделение клетки при zoom и pan; сортировка за башнями и деревьями; туман войны; неизвестные юниты; ускорение ×2; пропуск; reduced motion; возвращение из background; небольшой телефон. Не менять сервер, протокол и баланс при интеграции.

Открыть preview.html через HTTP static server (ES modules не запускать через file://). Тестовая сцена использует вымышленные позиции и не подключена к Railway или аккаунту игрока.


## Дополнение: сцена боя, версия 2

Детализированы ворота, факелы, кладка, плащи и пояс юнита. Добавлены drawBank, drawShrub, drawSmoke; состояния hit и defend. В preview — режимы удара с поражением, стрелы, захвата со сменой цвета знамени, строительства и защитной стойки. Экранные кнопки привязаны к проекции выбранного отряда; это демонстрационные действия, не игровые команды. Числа ресурсов и цель в шапке — статические примеры.

Снижение движения отключает дымовое движение, шаги, покачивание, реакцию от удара; строительство сразу показывает завершённую форму. Событийная смена состояний остаётся видимой. Начальный масштаб зависит от ширины экрана, управление перетаскиванием поддерживает pointer events. Pinch-zoom, реальные команды, стриминг большой карты и интеграция с TimelinePlayer остаются задачей игрового клиента.

Это всё ещё процедурный геометрический прототип. Он не достигает художественной детализации исходного референса; потребуются дальнейшая работа с формами, материалами и авторскими ассетами.


## Raster atlas pass

kingdom-atlas.png — 1254×1254 RGBA, six generated sprites: castle, conifer cluster, rocks, guard, archer, bridge. Generated with built-in image generation; prompt direction: consistent isometric stylized miniatures, ivory stone/cobalt roofs, upper-left lighting, transparent background, six separate objects. sprite-atlas.js defines explicit source rectangles, scale and ground anchors; preview now consumes the atlas. Original art is preserved unmodified.

Important: this is a candidate art pack, not final production animation. Only one direction and one pose per unit exist. Movement and hits transform the whole sprite; no walk-cycle frames or independent limbs yet. Both teams currently share blue sprite artwork; ownership is distinguished by HP markers and a separate city flag. Other faction textures, true animated flags, staged construction art, full terrain art, mobile-device performance checks and live-client integration are outstanding. Construction preview uses a percentage over the completed sprite. Do not ship this as complete faction visuals. Bridge is mirrored at draw time to align with the crossing.
