# Ограничения и незавершённые функции (v0.2)

## Этап 1 — что осталось

- **Графика и анимации** — передаются отдельному исполнителю (см. RENDERER_CONTRACT.md). Сейчас есть только отладочный вид сверху; он не проверялся в реальном Telegram-клиенте, только сборкой и типами.
- **Telegram** не проверен вживую: подпись initData покрыта тестами по алгоритму Telegram, но реальный токен в окружении разработки не использовался. Нужен первый запуск на Railway с `BOT_TOKEN`.
- Один народ (`union`), четыре типа войск, четыре технологии — объём этапа 1.

## Этап 2 — большой мир

- Генератор на 256×256 работает (~4 с, обычно со 2-й попытки), но порог честности старта и расстояние между 32 столицами нужно подобрать; генерация делается внутри транзакции старта партии — для 256×256 её стоит вынести в фоновую задачу.
- Нагрузка (`npm run bench`, 32 игрока, ~2 100 отрядов, 256×256): расчёт хода 160–220 мс, ИИ ботов ~2 с, событий ~3 000 (≈400 КБ). **Снимок хода ≈3 МБ** — в основном исследованные клетки 32 игроков в base64; перед этапом 2 перевести на битовые маски/RLE. Сохранение в PostgreSQL на полном объёме ещё не замерялось.
- `GET /state` и `/chunks` загружают состояние партии целиком на каждый запрос — для 256×256 нужен кеш состояния на время хода.
- Долгие маршруты на несколько ходов, дороги как строительство, порты, мини-карта — не реализованы (в данных есть признаки `Road`/`Bridge`).
- Таблицы `tiles`, `buildings`, `diplomacy` созданы заранее, логика к ним — на этапах 2–4.

## Этапы 3–4

- Выбор улучшения при повышении ранга (сейчас ранг даёт фиксированный бонус).
- Подавление, зона контроля, высота, отталкивание, командиры, снабжение, специализации городов, постройки.
- Дипломатия, очки влияния, лимит ходов, замещение выбывших ботами.

## Известные упрощения

- Нейтральные города охраняет пехотинец; нейтральные отряды не действуют.
- Отряд без приказа стоит на месте без бонуса; укрепление — только по явному приказу «удержание».
- Предупреждение о конце планирования отправляется для ходов от 1 часа (за 30 минут).
